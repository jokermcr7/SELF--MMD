# Telegram Diamond Games v1

ربات بازی با امتیاز مجازی؛ رابط بازی فقط در گروه تعیین‌شده با `GAME_CHAT_ID` فعال است. اگر این متغیر تنظیم نشود، نسخهٔ حاضر از شناسهٔ پیش‌فرض `-1003816728822` استفاده می‌کند. در پی‌وی، `/start` فقط حساب کاربر را ثبت می‌کند و هیچ منوی بازی ندارد.

## راه‌اندازی Railway
1. فایل‌ها را در GitHub repository قرار بده.
2. در Railway سرویس را از Repo بساز؛ Dockerfile به‌صورت خودکار استفاده می‌شود.
3. PostgreSQL را به همان Railway Project اضافه کن و `DATABASE_URL` را از متغیرهای سرویس دیتابیس بگیر.
4. در Variables سرویس ربات این متغیرها را وارد کن:
   - `BOT_TOKEN`: توکن جدید BotFather
   - `OWNER_ID`: شناسه عددی مالک
   - `GAME_CHAT_ID`: شناسه عددی گروه بازی؛ این نسخه اگر متغیر خالی باشد، به‌صورت پیش‌فرض `-1003816728822` را استفاده می‌کند. می‌توانی آن را در Variables هم صریحاً وارد کنی.
   - `DATABASE_URL`: اتصال PostgreSQL
   - `STARTING_DIAMONDS`: موجودی شروع، پیش‌فرض 100
   - `JOIN_TIMEOUT_SECONDS`: مهلت پیوستن، پیش‌فرض 180
   - `MAX_STAKE`: سقف هزینه ورود
   - `RANDOM_ORG_API_KEY`: کلید API از RANDOM.ORG؛ اگر خالی باشد، از مولد امن سیستم استفاده می‌شود و منبع نتیجه صریحاً اعلام می‌شود.
5. ربات را به گروه بازی اضافه کن. برای بازی عادی لازم نیست ادمین باشد، اما باید بتواند پیام ارسال و دکمه‌ها را مدیریت کند.
6. کاربرها باید یک بار ربات را در پی‌وی `/start` کنند تا حسابشان ثبت شود.

## قابلیت‌ها
- ثبت بازیکن و موجودی الماس
- پنل مالک از طریق دستورات خصوصی
- افزودن/کم‌کردن/تنظیم موجودی
- تاریخچه تراکنش و آمار
- بازی فقط در گروه تعیین‌شده: `بازی 20`
- دونفره، سه‌نفره، بازی با ربات، پیوستن با دکمه
- جایزه سیستمی ثابت برای برنده؛ امتیاز بازنده‌ها به برنده منتقل نمی‌شود
- لغو توسط سازنده و بازپرداخت هزینه ورود
- بازپرداخت خودکار بازی‌های کاربران که در مهلت تکمیل نشده‌اند
- استفاده از RANDOM.ORG در صورت تنظیم API Key؛ در صورت خطای سرویس بازی با ربات بازپرداخت می‌شود

## دستورات مالک (فقط در پی‌وی)
/admin_help
/give USER_ID AMOUNT
/take USER_ID AMOUNT
/setdiamonds USER_ID AMOUNT
/balance USER_ID
/ledger USER_ID
/stats

## کاربران
در پی‌وی: `/start` فقط ثبت حساب
در گروه بازی: `بازی 20` برای ساخت بازی، `/balance` برای موجودی

## امنیت
توکن را در GitHub عمومی قرار نده. اگر توکن قبلی را جایی منتشر کرده‌ای، آن را در BotFather باطل کن و توکن تازه بساز.

## قواعد امتیاز
هزینه ورود هر شرکت‌کننده از موجودی خودش کم می‌شود. برنده پاداش ثابت `۲ × هزینه ورود` از سیستم دریافت می‌کند. امتیاز بازنده‌ها مستقیماً به برنده منتقل نمی‌شود. این سیستم برای امتیاز مجازی است و نباید به پول واقعی یا جایزه قابل‌نقد تبدیل شود.


## پنل ورود سلف (افزوده‌شده)
- در پی‌وی ربات دستور `/panel` را بفرست تا تصویر پنل و دکمه‌های ورود نمایش داده شوند.
- برای ورود باید `TG_API_ID` و `TG_API_HASH` از `my.telegram.org` و یک `SESSION_SECRET` خصوصی در Variables تنظیم شوند.
- کد ورود و در صورت نیاز رمز دومرحله‌ای در همان پی‌وی وارد می‌شوند؛ نشست ذخیره‌شده رمزگذاری می‌شود.
- برای دیتابیس پایدار در Railway، PostgreSQL را متصل کن؛ SQLite روی دیسک موقت ممکن است بعد از استقرار مجدد از بین برود.
- این نسخه فقط ورود و ذخیره نشست را اضافه می‌کند؛ خودش امکانات خودکارسازی سلف را اجرا نمی‌کند.
